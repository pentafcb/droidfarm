🚜 Jerusalem 1.0 Multi-Host System
How It Works — Operator Guide

Version: 2.0 (multi-host)  |  Date: October 5, 2026

1. Big Picture

Jerusalem 1.0 runs Android instances (each with Roblox) across multiple machines. One machine is the Main Node — it hosts the dashboard you use and decides where each instance runs. Every other machine is a Provider (worker) running a silent background program called the Wing Agent.

┌─────────────────────────┐ ┌─────────────────────────┐ │ MAIN NODE │ │ PROVIDER PC #1 │ │ (your main VPS) │ │ (Linux VPS or PC) │ │ │ │ │ │ ┌─────────────────┐ │ HTTPS │ ┌─────────────────┐ │ │ │ Dashboard │ │◄───────►│ │ Wing Agent │ │ │ │ (port 8080) │ │ API │ │ (port 8090) │ │ │ └─────────────────┘ │ │ └────────┬────────┘ │ │ ┌─────────────────┐ │ │ │ manages │ │ │ Orchestrator │──┼─────────┘ ┌─────▼─────┐ │ │ │ (providers, │ │ │ Docker │ │ │ │ placement) │ │ │ +Waydroid │ │ │ └─────────────────┘ │ └───────────┘ │ └─────────────────────────┘ └─────────────────────────┘ ▲ ▲ │ ┌──────────────────┐ │ └────────────│ PROVIDER PC #2 │────┘ │ (Windows PC) │ │ Wing Agent hidden│ │ (no window) │ └──────────────────┘

Key idea: you only ever touch the dashboard on the main node. The main node forwards every action (create, tap, screenshot, delete) to the correct provider PC automatically.

2. Adding a Provider PC

In the dashboard, click Providers → + Add provider. You get two one-line commands (token expires in 1 hour). Run the matching one on the new machine:

Linux (run as root)

curl -sSL -H "X-Join-Token: <TOKEN>" http://<MAIN_IP>:8080/api/install/install-wing.sh | sudo bash

Windows (run in PowerShell)

powershell -WindowStyle Hidden -Command "curl.exe -sSL -H 'X-Join-Token: <TOKEN>' http://<MAIN_IP>:8080/api/install/install-wing.bat -o $env:TEMP\wing.bat; Start-Process $env:TEMP\wing.bat -WindowStyle Hidden"

That's it. The script does everything silently:

  • Linux: installs Docker, sets up binder (needed by Waydroid), downloads the Android image from the main node (~212 MB), installs the wing agent as a systemd service (starts on boot, restarts if it crashes), registers with the main node. No windows, no prompts.
  • Windows: installs Python silently if missing, copies the agent to C:\ProgramData\<random-codename>\ (each node gets its own random codename), creates a hidden scheduled task that runs at boot as SYSTEM via pythonw.exe (no console window, ever), opens the firewall port, registers with the main node. Nothing ever appears on screen.
Hidden by design: on Linux the agent is a systemd service with no terminal output. On Windows it runs via pythonw.exe (the windowless Python) as a SYSTEM scheduled task — no taskbar icon, no console, no popup. The only visible trace is a random-codename entry in Task Scheduler.

3. How a Machine Becomes a Provider

  1. Dashboard generates a one-time join token (valid 1 hour).
  2. The install script downloads agent.py from the main node using that token.
  3. The script calls POST /api/providers/register with the token, hostname, and OS.
  4. The main node verifies the token (and burns it), creates a provider ID (e.g. p_6bba740a3bf3) and a secret agent key, and returns them.
  5. The agent saves the key locally and starts its HTTP server on port 8090.
  6. Every 30 seconds the agent heartbeats to the main node with CPU/RAM stats. If a provider misses heartbeats for 2 minutes, the dashboard marks it offline.

4. Assigning Instances to PCs

When you click + New instance, the "Run on" dropdown lets you choose:

OptionWhat happens
Auto (least loaded)The main node picks the provider (or itself) with the most free RAM that can fit the instance. Best for most cases.
Main node (local)Runs on the main VPS, like before.
A specific providerPins the instance to that PC. Only online providers are listed.

Each instance card shows 📍 where it runs (e.g. "📍 Main node" or "📍 Office-PC"). All controls — View, tap, Launch Roblox, Stop, Delete — work identically regardless of where the instance lives. The main node proxies them to the right wing agent.

5. What the Wing Agent Does

The agent (agent.py, ~450 lines, Python standard library only — no dependencies to install) exposes a small HTTP API that only the main node can call (authenticated by the per-provider agent key in the X-Agent-Key header):

EndpointPurpose
GET /api/agent/healthAlive check (no auth needed)
GET /api/agent/statsCPU %, RAM %, core count
GET /api/agent/instancesList local Android instances + status
POST /api/agent/instancesCreate instance (Docker + Waydroid + Roblox)
DELETE /api/agent/instances/<name>Delete instance + its data
POST /api/agent/instances/<name>/start|stopStart/stop container
POST /api/agent/instances/<name>/inputTap / key press (instant, via FIFO)
GET /api/agent/instances/<name>/screenshotLatest screen PNG
POST /api/agent/instances/<name>/launch-robloxOpen Roblox

How instances stay fast

  • Instant input: each Android container runs a tiny input daemon that reads commands from a FIFO pipe. Taps go straight into the pipe — no 27-second shell startup delay.
  • Live screen: a screencap loop inside each container captures the screen several times per second. The dashboard streams these frames over WebSocket (~9 fps).
  • Roblox auto-install: every new instance installs Roblox 2.740.931 (x86_64) automatically during setup — the latest version that runs on these virtual Androids.

6. Security Model

  • Join tokens are single-use and expire after 1 hour. They only grant the right to download the installer and register once.
  • Agent keys are 32-byte random secrets, unique per provider, stored with 600 permissions. All main→wing calls require the key.
  • Dashboard still uses your password (sober) with bearer tokens.
  • Wing agents only accept commands from the main node (key check); anyone without the key gets 401 Unauthorized.

Note on Windows: the Windows wing agent installs silently, registers, and reports stats today. Running Android instances on Windows needs a Windows-compatible Android runtime — Waydroid itself cannot run on Windows. Tell Penta's assistant which route you prefer (WSL2 + Waydroid experimental, or a Windows emulator driven via ADB) and the driver can be plugged into the agent's existing API.

9. Troubleshooting

  • Provider shows offline: check the worker has network access to the main node on port 8080, and that the wing service/task is running (Linux: systemctl status <codename>.service).
  • Install script fails: copy the current static join token from the dashboard (Nodes → + Add node) — it does not expire, so a 403 means the token was mistyped, not stale.
  • "No free IP on provider": the provider's 10.20.0.x range is full (max ~240 instances per provider).
  • Instance stuck on "Booting…": the Android container is still starting (takes 1–3 minutes on first boot while Roblox installs).
